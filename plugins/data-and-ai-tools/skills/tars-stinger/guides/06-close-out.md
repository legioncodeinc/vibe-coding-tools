# 06. Close out

1. Reconcile each PR, proof and deploy with current observed state. Mark local-only, queued, unproven and handed-off work honestly; a plan, chip offer or merged PR is not shipment. A row is shipped only after a verify pass proves it against running code and real-database tests ([08](08-lessons-2026-11-02.md), rule 2). List every `UNAPPROVED DEFERRAL` as not done.
2. Save `references/templates/manager-handoff.md` in the local effort folder. Include owner decision sources, scoped delegation, CASE verdicts and conditions, KIPP cards/index, reserved and confirmed numbering, pending questions, owned worktrees and exact candidate proofs.
3. Never automatically archive CASE or KIPP. Leave them idle with their remaining work recorded. Archive finished work chips only under the owner's scoped authorization and the host's approval controls; no default permission comes from this skill.
4. `CronDelete` created ticks and `TaskStop` created poller/fallback jobs. Run `node <skill>/scripts/tars-registry.mjs unregister` so the compaction hook stops briefing this session. Confirm timer, monitor and registry stop state with the live tools (`tars-registry.mjs show`). Do not modify unrelated watchers or sessions.
5. Append the ledger's final event and give the required closing report: status, delivered, verified, not done, owner questions and out-of-scope observations. Report actual checks and unfinished gates; no automatic commit, push, promotion or deployment follows close-out.
