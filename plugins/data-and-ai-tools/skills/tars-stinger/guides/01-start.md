# 01. Start: arm TARS before any work chip

Derived from `distilled-tars.md` D1, D3, D4, D5.

1. **Load the tools** in one call: `ToolSearch` with `select:mcp__ccd_session__start_session,mcp__ccd_session__dismiss_task,mcp__ccd_session_mgmt__list_sessions,mcp__ccd_session_mgmt__get_session,mcp__ccd_session_mgmt__list_events,mcp__ccd_session_mgmt__stop_session,mcp__ccd_session_mgmt__archive_session,mcp__ccd_pr__get_status,SendMessage,ReadNotifications,CronCreate,CronList,CronDelete,Monitor,TaskStop`. Skip any already loaded. `start_session` was named `spawn_task` in older desktop builds; load whichever the host lists. If neither it nor `list_events` loads, stop: this is not a Claude Code desktop session, and TARS cannot manage here. Say so in one line.
2. **Load the manager profile and roles.** Read `07-case-and-kipp.md`; fill or restore `references/templates/owner-profile.md` from current owner instructions. Verify the chosen model and effort, repo/ref, domain map, delegation and contact cadence. Do not change session settings.
3. **Make the state folder** (`references/REFERENCE.md`, State layout), copy `references/templates/ledger.md` to `ledger.md`, and create an empty `watch.txt`.
4. **Register this session** so it survives a compaction: `node <skill>/scripts/tars-registry.mjs register <state-folder>`. The session id comes from `$CLAUDE_CODE_SESSION_ID` (or pass `--session <id>`). Check the entry with `tars-registry.mjs show` and record the session id and UTC time in the ledger. The registry only helps where the `tars-compaction.mjs` hook is bound (the Wasp Nest Core plugin or an `install.sh` home install); without it the entry is harmless, and the fallback is the owner saying "re-ingest /tars". A `/clear` starts a new session id, so register again after any clear. What the hook does: [08](08-lessons-2026-11-02.md).
5. **Take stock.** `list_sessions` (and `linked: true`). Record any session already doing work the owner asked for; manage it instead of spawning a duplicate, after the owner says yes in one line. Never stop or re-brief a session TARS did not spawn without that yes.
6. **Spawn CASE first, then KIPP** from `references/templates/case-brief.md` and `kipp-brief.md`. CASE is the adviser and read-only systems and CI watcher; fill its watch list from the profile. KIPP is the idea factory and PRD writer. Offer both with `start_session` during this owner-typed turn; a tick cannot start them ([08](08-lessons-2026-11-02.md), rule 5). Restore prior transcript tails and handoff read-only. Record each task ID and link the actual desktop session when it starts. Use the owner's accessible interface; an offered chip is not a running session.
7. **Arm the 10-minute tick**: `CronCreate` with cron `*/10 * * * *` and the prompt from `references/templates/tick-prompt.md`, with its `Managed sessions` line filled in. Record the id. Recreate the cron whenever that roster changes (`03-ten-minute-tick.md` step 5). Tell the owner once that recurring jobs expire after 7 days and live only in this session.
8. **Arm the CI poller** as a `Monitor`: command `bash <skill>/scripts/ci-poll.sh <state-folder>` with `IGNORE_CHECKS` and `REQUIRED_CHECK` set for the repo, `timeout_ms` 1800000, description "TARS CI poll (1 min)". Record it. An empty `watch.txt` is fine; the poller re-reads it every loop.
9. **Verify once by hand**: confirm the health URL or required check name you will trust actually exists (one `curl` or `gh pr checks` on a recent PR). Record the result.
10. Then, and only then, spawn work chips (`02-spawn-and-track-chips.md`).

If CASE has not started within ten minutes, apply the scoped fallback and waiting rules in `07-case-and-kipp.md`. Never substitute a background adviser for the separate Desktop manager team without recording that limitation.
