# Guide: install-tier

Grounded in `references/research/distilled-ci-to-deploy-posture-and-tiers.md` and `../references/tier-taxonomy-and-install-runbooks.md` (runbooks per tier, raw citations there).

Install the right tier of release flow into a target repo. Installation changes the repo and often GitHub/Vercel settings: it requires an explicit owner instruction for THIS action, and settings changes (branch protection, repo variables, environment rules) are side-effecting external calls.

1. **Audit first.** Run `audit-posture.md` unless a fresh audit exists. Install without an audit guesses at blast radius.
2. **Confirm the target tier with the owner.** State the current tier, the proposed tier, and the ladder trigger condition that justifies the upgrade (0->1 anyone else depends on the product; 1->2 deploys must be reviewable/rollback-able artifacts; 2->3 money/auth/queues/migrations or multiple operators). Do not install a tier the owner did not pick.
3. **Install per the tier runbook** (`../references/tier-taxonomy-and-install-runbooks.md`):
   - **Tier 1:** add `required_status_checks` via the classic protection endpoint (aggregate check if lanes skip jobs); add the deploy workflow with `concurrency` (cancel-in-progress: false for production) and `environment: production`.
   - **Tier 2:** disable Auto-assign Custom Production Domains; CI deploys with `--skip-domain` (or staged production builds); add the promote step (`vercel promote <url> --timeout`, `vercel promote status`); document Instant Rollback as the recovery path.
   - **Tier 3:** port the worked pattern, not Reachlynk's script names: freeze repo variables; live locks via the classic endpoint; `workflow_dispatch` workflow bound to an exact 40-char SHA with a computed confirmation input; serialized concurrency; preflight asserting SHA identity + checks-on-exact-SHA (check-runs API, never merge-ref PR checks) + live lock reads + environment branch policy + actor identity; execute job (migrations one transaction per file, candidate verify, promote exactly the recorded candidate, queues resumed, receipts always uploaded); post-deploy smoke comparing the live release marker. Plus the supporting protocol: release-wait + merge-queue parking file + notify workflow, published in repo agent rules.
4. **Respect blast radius.** Before editing any shared surface (workflows, package files, shared scripts), inventory what pins/hashes/contracts reference it (reviewed-bytes pins, release-contract tests) and update them in the same change. Check names you introduce must be unique per branch.
5. **Verify the install.** Exercise the flow end to end at the smallest safe scale: Tier 1 (a PR is gated, a merge deploys), Tier 2 (a deployment lands Staged, promote reaches Current), Tier 3 (a preflight against a non-release SHA fails closed with the right refusal class, and a real dispatch follows the owner-authorization rules for production effects). Record run URLs as evidence.
6. **Document.** Write the required-check posture doc (which checks required where, and why) and the release runbook into the repo (docs/ or library/, per repo convention). An undocumented Tier 3 is a Tier 2 with extra failure modes.
