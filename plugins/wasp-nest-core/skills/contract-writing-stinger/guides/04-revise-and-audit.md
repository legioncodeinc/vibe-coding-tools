# Revise an agreement and audit drift

1. Compare the requested behavior to the accepted `CTR` record, its native schema, code, and every linked PRD. Identify the exact normative rule that changes. An accepted record's behavior and revision are immutable; draft revisions may change before acceptance. [../references/research/raw/semantic-versioning.md](../references/research/raw/semantic-versioning.md)
2. Classify compatibility against the declared interface. A removal, requiredness change, incompatible type change, or changed meaning is presumptively breaking until both sides prove otherwise. A compatible addition may still need a mixed-version rollout check. Do not infer a deployed SemVer bump from a `CTR` number. [../references/research/raw/semantic-versioning.md](../references/research/raw/semantic-versioning.md) [../references/research/raw/protobuf-best-practices.md](../references/research/raw/protobuf-best-practices.md)
3. List every provider, consumer, PRD, schema, and verification obligation affected. Draft a new `CTR` number with `Supersedes: CTR-<old> revision <n>`, leaving the accepted predecessor unchanged while the proposal is open. Present the proposed agreement and migration to Mario. Do not repin PRDs yet.
4. On acceptance, freeze the successor, set its acceptance evidence, and add `Superseded by: CTR-<new> revision <n>` to the predecessor while changing only the predecessor's status to `Superseded`. Keep all old normative terms and acceptance evidence intact. Ask Library to repin active affected PRDs; completed historical PRDs keep their original pin. Require each party to run its checks against the new agreement. [../references/research/raw/pact-contract-testing.md](../references/research/raw/pact-contract-testing.md)
5. During routine PRD or library drift scans, look for unresolved relative links, active PRDs pinned to a superseded agreement, accepted records contradicted by code or native schemas, and new shared boundaries lacking a `CTR`. Use `scripts/validate_contracts.py` for structure and links, then review semantics manually. A static document cannot establish implementation conformance. [../references/research/raw/pact-contract-testing.md](../references/research/raw/pact-contract-testing.md)

The CTR immutability, numbering, and approval mechanism is a Wasp Nest workflow convention. SemVer supplies compatibility vocabulary only where the interface actually uses SemVer. [../references/research/distilled-contract-writing.md](../references/research/distilled-contract-writing.md)
