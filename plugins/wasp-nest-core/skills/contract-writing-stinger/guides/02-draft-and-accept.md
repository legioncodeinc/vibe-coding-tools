# Draft and accept a CTR record

1. Confirm the repository's `library/` root and scan `library/knowledge/private/contracts/CTR-*.md`. For a new boundary, use the highest existing number plus one, zero-padded to at least three digits. Never reuse an old number. Keep the file directly under `contracts/`, independent of PRD lifecycle folders.
2. Copy `templates/contract-template.md` to `library/knowledge/private/contracts/CTR-<###>-<slug>.md`. Set status `Draft`, revision `1`, and `Accepted by: Pending`. Fill every section with sourced facts, proposed terms clearly marked, and exact open decisions. One record should describe one independently changeable boundary.
3. Specify the protocol details that apply. For HTTP, include method, path, inputs, outputs, errors, auth, and version. For events, include channel, producer, consumer, payload, headers or correlation, delivery and failure. For shared data, include types, requiredness, nullability, identifiers, owner, and access rules. Link existing native schemas and quote their versions. [../references/research/raw/openapi-specification.md](../references/research/raw/openapi-specification.md) [../references/research/raw/asyncapi-specification.md](../references/research/raw/asyncapi-specification.md) [../references/research/raw/json-schema-specification.md](../references/research/raw/json-schema-specification.md)
4. Add one valid synthetic example and one error or edge case. Name a provider check and a consumer check with evidence locations. A drafted test does not establish conformance, and a provider-only test does not prove the consumer uses the interface correctly. [../references/research/raw/pact-contract-testing.md](../references/research/raw/pact-contract-testing.md)
5. Present the exact proposed rules and any unresolved choices to Mario. Revise the Draft as needed, incrementing its local revision and history. Only his explicit acceptance of the exact current revision changes status to `Accepted`. Record date and decision reference in `Accepted by`. An accepted record has `Open decisions: - None.` and no template placeholders. Freeze its normative content after acceptance. If acceptance is missing, keep `Draft` and tell Library which PRDs remain blocked.
6. Run `python3 scripts/validate_contracts.py <repository-root>` and fix structural or link findings. This check validates records and links, not agreement correctness or running implementations.

The accepted status, owner gate, path, and numbering are Wasp Nest conventions approved for this workflow. They are not prescribed by OpenAPI or Pact. [../references/research/distilled-contract-writing.md](../references/research/distilled-contract-writing.md)
