# Guide 02: build hot-lead follow-up

Use this guide only after Guide 01 returns `HOT` and readiness is `READY` or `DRAFT_WITH_GAPS`.

## 1. Identify the hot signal

Write one internal sentence that names the exact trigger, source, and time. Examples include a real request for a demo, quote, pricing, proposal, trial assistance, or a decision answer. If that sentence cannot be written from evidence, return to classification.

Prompt handling is directionally supported by current SparrowCRM guidance and HighLevel community evidence, but the community timing claim is not a benchmark. [../references/research/raw/2026-08-10-sparrowcrm-lead-follow-up.md] [../references/research/raw/2026-06-15-reddit-highlevel-speed-to-lead.md]

## 2. Choose the real next step

Prefer, in order:

1. A next step already agreed with the lead.
2. A direct answer to the lead's actual question.
3. Two low-friction options that both exist and are approved.
4. One plain-text reply request.

Do not default to a calendar link when the lead asked for information. Do not offer a call duration, availability, price, discount, or deadline that intake did not supply.

## 3. Map one new reason per step

Before drafting, fill this internal table:

| Step | Verified reason to send | Primary action |
|---|---|---|
| H0 | Direct answer or accurate summary | One next step |
| H1 | Useful detail not already sent | One choice |
| H2 | Verified decision aid, answer, or resource | One question |
| H3 | Current-priority check | Small reply |
| H4 | Close active loop | Easy route back |

If two rows repeat the same reason, revise the map or remove a step. Hunter and Belkins both argue for a new angle rather than a recycled reminder. [../references/research/raw/2026-06-12-hunter-three-follow-ups.md] [../references/research/raw/2026-06-26-belkins-sales-follow-up-statistics.md]

## 4. Draft from the reusable sequence

Open `../references/templates/hot-lead-sequence.md`. Preserve its send conditions and replace only evidence-backed fields.

- Keep the real subject when a real thread exists.
- Use an accurate new subject when no thread exists.
- Keep H0 direct and useful.
- Make H1 and H2 materially different.
- Reduce friction in H3.
- Make H4 the actual end of active follow-up.

HighLevel and Hunter support threaded sequences and stop-on-reply behavior, but those capabilities apply to real message history. [../references/research/raw/2026-06-11-highlevel-email-sequences.md] [../references/research/raw/2026-06-12-hunter-three-follow-ups.md]

## 5. Apply event branches

- Proposal: follow the agreed date, or use the current 2 to 3 day vendor starting point when the operator approves it.
- Trial: use the real end date and actual usage only.
- Lead-stated timing: acknowledge it and suppress default steps until the stated date.
- Objection: answer only the objection the lead actually raised.
- Human reply: stop the sequence and hand the thread to the owner.

SparrowCRM's event-specific templates are useful as situational structures, not as permission to invent an event. [../references/research/raw/2026-08-10-sparrowcrm-lead-follow-up.md]

## 6. Return the deliverable

Provide:

1. Plan card from Guide 01.
2. Sequence table with step, timing, reason, CTA, and exit condition.
3. Plain-text drafts labeled H0 through H4.
4. Unresolved evidence placeholders.
5. Handoff and suppression rules.
6. QA and measurement work still required.

Never present a `DRAFT_WITH_GAPS` sequence as ready to send.
