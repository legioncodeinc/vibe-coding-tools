# 01. Rollup procedure: leaf to sub-audit to category to final

This guide walks the three-tier rollup formula from build plan section 4.3 as it is actually
implemented in `references/templates/website-audit-scorecard-template.xlsx`, generated by
`references/scripts/generate-scorecard-xlsx.py`. Read `03-nesting-structure-design.md` first
if you have not already - it explains why the hierarchy has the shape it does before this
guide walks the formulas that populate it.

## 1. The four levels

| Level | Where it lives | What it computes |
|---|---|---|
| Leaf | `Scorecard` sheet, one row per checkpoint, column E | A single 0-6 score written by whichever Drone produced the finding, transcribed here by audit-scoring-wasp-drone from a validated `leaf-finding.schema.json` record. Never a formula. |
| Sub-audit | `Scorecard` sheet, one "rollup" row right after each sub-audit's leaf block, column L | The N/A-aware weighted average of that sub-audit's own leaf rows. |
| Category | `Scorecard` sheet, one "CATEGORY ROLLUP" row after each category's sub-audits, column L | The N/A-aware weighted average of that category's sub-audit rollups. |
| Final | `Executive Scorecard` sheet, "FINAL SCORE" row | The N/A-aware weighted average of all 8 category rollups, using `CategoryWeights` from `Rubric`. |

## 2. The formula, sourced

Build plan section 4.3 states the leaf-to-sub-audit formula as:

```
sub_audit_pct = SUMPRODUCT(scores, weights, --(scores>0))
              / (6 * SUMPRODUCT(weights, --(scores>0)))
```

This is the exact masked-SUMPRODUCT pattern documented in
`references/research/distilled-audit-scoring.md` section 2, itself sourced from
[raw/datacamp-com-tutorial-sumproduct.md] (the `--` double-unary mask converting a boolean
test to 1/0 and multiplying it into the SUMPRODUCT so an excluded row contributes nothing to
either side of the division) and corroborated by [raw/autorubric-org-docs-api.md]'s
independent `CANNOT_ASSESS`/exclude-from-both-sides pattern from the LLM-rubric domain. The
`/SUM(weights)`-style self-correcting divisor (here, `/ (6*SUMPRODUCT(weights, mask))`) is the
more robust form recommended over a bare `SUMPRODUCT(...)` in
[raw/exceljet-net-formulas-weighted-average.md] and [raw/datacamp-com-tutorial-sumproduct.md],
because it keeps working even if a category's weights do not sum to a round number - a
documented common defect per [raw/portfoliohub-io-blog-project-prioritization-template.md]
("weights that quietly sum to 1.15").

The actual formula written into every sub-audit rollup cell (column L) is:

```
=IF(SUMPRODUCT(--(E{first}:E{last}>0),H{first}:H{last})=0,"N/A",
   SUMPRODUCT(--(E{first}:E{last}>0),E{first}:E{last},H{first}:H{last})
   /(6*SUMPRODUCT(--(E{first}:E{last}>0),H{first}:H{last})))
```

`{first}:{last}` is that sub-audit's own contiguous leaf-row range. `H` is the per-leaf weight
column (defaults to 1 for every leaf; see `03-nesting-structure-design.md` for why leaf
weights are plain cell values rather than named ranges). The outer `IF(...=0,"N/A",...)` is
the zero-denominator guard from [raw/exceljet-net-formulas-weighted-average.md]
(`=IF(SUM(Weights)=0,"No weights",...)`), needed here specifically because every leaf in a
sub-audit being N/A is a real, expected case (e.g. a commerce-only sub-audit on a
non-commerce site) that must resolve to a visible "N/A" rather than a `#DIV/0!` error.

**Why both sides of the division must share the identical mask.** This is flagged in the
distilled research as an inference built from, not a verbatim statement of, the SUMPRODUCT
source's documented mechanism [raw/datacamp-com-tutorial-sumproduct.md]. If only the
numerator excluded N/A rows while the denominator kept summing every row's weight
unconditionally, an N/A leaf's weight would still deflate the result even though its score no
longer contributes to the numerator - the average would be silently wrong, dragged down by
criteria that do not apply. The formula above uses `--(E{first}:E{last}>0)` as the mask in
BOTH `SUMPRODUCT` calls for exactly this reason. Hand-verify this yourself before trusting a
retuned formula: change one leaf to 0 (N/A) and confirm the sub-audit rollup does not move
unless every other leaf's relative weight also changes.

## 3. Category rollup: the "compact mirror" trick (engineering design, not sourced)

Build plan section 4.3's sub-audit-to-category formula is:

```
category_pct = SUMPRODUCT(sub_audit_pcts, sub_weights) / SUM(sub_weights)
```

This is straightforward when `sub_audit_pcts` and `sub_weights` are two arrays of the same
length in the same order. The complication - not addressed by any source in the research
archive, since neither round's sources describe a multi-level hierarchy at all
(`references/research/distilled-audit-scoring.md` section 4's "what this source does NOT
provide") - is that a category's sub-audit rollup rows on the `Scorecard` sheet are NOT
contiguous with each other; each is followed by that sub-audit's own leaf block before the
next sub-audit's rollup row appears. `SUMPRODUCT` requires its arrays to be the same shape, so
a formula cannot reach across that gap directly.

The template's own fix (this Stinger's engineering design, not sourced): immediately after a
category's last sub-audit rollup row, a small contiguous "mirror" block is written - one row
per sub-audit, each cell a plain formula pulling that sub-audit's own rollup value
(`=L{source_row}`). Because this mirror block IS contiguous and in the same order as the
category's `SubWt_<key>` named range on `Rubric`, the category rollup formula can then do:

```
=IF(SUM(SubWt_<key>)=0,"N/A",
   SUMPRODUCT(L{mirror_first}:L{mirror_last},SubWt_<key>)/SUM(SubWt_<key>))
```

matching build plan section 4.3's formula exactly, with the same zero-denominator guard.

## 4. Final rollup

Build plan section 4.3:

```
final_pct = SUMPRODUCT(category_pcts, category_weights)
```

The template implements this on `Executive Scorecard` using a local 8-row summary table
(Security through Content Score, in the exact descending order from build plan section 4.2)
whose "Rollup %" column pulls each category's rollup cell from `Scorecard` by direct
cross-sheet reference, and whose weight is the `CategoryWeights` named range from `Rubric`
directly:

```
=SUMPRODUCT(C{first}:C{last},CategoryWeights)/SUM(CategoryWeights)
```

The `/SUM(CategoryWeights)` divisor is the same self-correcting pattern as level one; the
`Rubric` sheet's own "Check: should equal 100" cell (conditionally formatted red if it drifts)
is a second, visible integrity check on top of it, directly modelled on
[raw/portfoliohub-io-blog-project-prioritization-template.md]'s "weight-check formula" and
"never typed, so nobody can nudge it" guidance for the rank/cumulative-total formulas in that
source's own worked example.

## 5. Verified, not just written

This is not a claim taken on faith. The generated template was recalculated end to end with
LibreOffice Calc in headless mode (`soffice --headless --convert-to xlsx ...`, which forces a
real formula recalculation rather than reading a possibly-stale cached value) and the computed
results read back with `openpyxl.load_workbook(..., data_only=True)`. With the template's own
illustrative example data (each sub-audit built from three leaves scored 6 and one leaf scored
0/N/A, except Security's first "Headers" leaf deliberately scored 1 to also exercise the
override in `02-critical-security-override.md`):

- Every sub-audit unaffected by the deliberate override leaf correctly rolled up to 100%
  (`3*6 / (3*6)`, i.e. the N/A leaf's weight was excluded from the denominator, not just the
  numerator - if it had NOT been excluded from the denominator the result would have been the
  wrong 75%, `18/24`).
- Security's own category rollup came out to 96.03% (dragged down only by the one deliberately
  low leaf, correctly averaged against its six other sub-audits at 100% each).
- The raw final score (before the override) computed to 99.2%, which is what triggered the
  demonstration in the next guide.

Re-run this verification any time the generator script changes:

```bash
python3 skills/audit-scoring-stinger/references/scripts/generate-scorecard-xlsx.py
soffice --headless --convert-to xlsx --outdir /tmp/xlsx-verify skills/audit-scoring-stinger/references/templates/website-audit-scorecard-template.xlsx
python3 -c "
import openpyxl
wb = openpyxl.load_workbook('/tmp/xlsx-verify/website-audit-scorecard-template.xlsx', data_only=True)
ex = wb['Executive Scorecard']
print(ex['C14'].value, ex['C20'].value, ex['C22'].value)
"
```
