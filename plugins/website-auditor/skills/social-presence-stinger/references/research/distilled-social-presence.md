# Distilled social-presence research

Dense reference distilled from `raw/`. Every claim below cites its source file in brackets. Organized around this Bee's actual job: a Facebook/LinkedIn/Instagram presence audit run via the harness's own browser tooling in wave W5, independent of `site-data/`, that explicitly prompts the user to authenticate per platform if deeper data is wanted, and defaults to a silent no-op (never a score penalty) when authentication is declined or unavailable. Round 3 closes the biggest gap flagged after round 2: exactly what is visible on each platform's public, non-authenticated profile view versus what structurally requires login, and platform-specific business-profile completeness signals. Five raw sources now feed this Stinger: two general social-media-audit-checklist vendor blogs from round 2, and two official-docs sources (Meta, LinkedIn) plus one technical vendor blog on Instagram's public-data API surfaces added in round 3.

Research window: round 2 sweep and round 3 deeper pass, both 2026-08-18.

## 1. What a social media audit is, and the audit-versus-strategy split

- A social media audit is defined as a structured review of all social accounts a brand manages, compiling and analyzing performance across platforms, described as functioning like "a report card": it identifies strengths, areas for improvement, and next steps. It is a snapshot at one point in time, distinct from an ongoing social media strategy, which is the forward-looking plan built on top of the audit's findings; the audit answers "what is working now," the strategy answers "where are we going." [raw/blog-hootsuite-com-social-media-audit.md]
- Framing for why this matters as a run order for this Bee: the source's own guidance is to run the audit first, then build or refine strategy on top of it, not the reverse. [raw/blog-hootsuite-com-social-media-audit.md]
- The second source frames the same discipline as a straightforward checklist run in about 60 minutes, organized into five sections: Profile, Content Performance, Analytics and Metrics, Competitors, and Strategy (only the first three sections survive in the archived text). [raw/posteverywhere-ai-blog-social-media-audit-checklist.md]

## 2. What is actually visible on a public, unauthenticated profile: the structural answer

This is the round-3 gap closure. Round 2's two sources described WHAT to check on a profile but did not establish, platform by platform, which of those checks are structurally possible without a login versus which are not. Round 3's official-docs and technical sources answer that directly.

- **Instagram, per Meta's own Help Center:** a fixed, non-hideable list of fields is "always public" for both public AND private accounts, visible to anyone, "on or off Instagram, even if they don't have an Instagram account": name, username, profile picture, bio, links, follower and following counts, avatar, Threads username, and channels created by the account. Meta's own language is explicit that this information "can't be hidden" by the account owner, no privacy toggle affects it. [raw/www-facebook-com-help-347751748650214.md]
- **Instagram, per a technical vendor source specializing in public-data APIs:** the practical test for "is this public" is opening a private browser window and visiting the profile; whatever is visible there is public data, "and no vendor changes that." Beyond the profile fields above, this extends to post-level data visible on a public profile's post history: caption, hashtags, media type, media URL, permalink, timestamp, and the public like/comment counts on a post. Explicitly named as NOT public, regardless of vendor claims: impressions, reach, saves, shares, profile visits, and audience demographic breakdown, all of which "sit behind the account holder's own login" and are called "a structural boundary, not a difficulty curve." [raw/www-getphyllo-com-post-social-media-public-data.md]
- **Instagram's official API surfaces are not actually "no-login" either**, which matters directly for how this Bee should think about its own no-auth default path versus its opt-in path: even Meta's Business Discovery surface (the only official route to read another account's public profile data programmatically) requires the AUDITOR to hold their own authenticated Instagram Business account and access token, and the TARGET account must itself be a Professional (Business or Creator) account, personal accounts return nothing through it. Meta's Hashtag Search surface likewise requires App Review, business verification, and an authenticated Business/Creator account, is capped at 30 unique hashtags per rolling 7 days, returns only the last 24 hours of media, and cannot return the poster's username at all (it returns the post, not the poster). The practical implication: there is no purely anonymous, zero-authentication OFFICIAL API path to Instagram profile data; a genuinely unauthenticated audit is a plain browser visit to the public profile page, not an API call, and is limited to what that browser view surfaces (the "always public" field list above, plus visible post history). [raw/www-getphyllo-com-post-social-media-public-data.md]
- **LinkedIn, per LinkedIn's own Help Center:** the logged-out "public profile" is explicitly described as "a simplified version" of the full profile, and LinkedIn states plainly, in its own words, that "in order to see your full profile, visitors may need to log in to their LinkedIn accounts." Unlike Instagram's fixed always-public field list, LinkedIn's public-profile fields are individually togglable BY THE PROFILE OWNER (photo, headline, summary/About, experience, skills, articles/activity, and more, per the source's own related settings article); the source states LinkedIn "may show an even more limited profile preview that includes some but not all of the profile fields" a member has allowed to be public. The default photo-visibility setting is Public, but every section's visibility is otherwise owner-controlled and not a fixed, guaranteed set. [raw/www-linkedin-com-help-linkedin-answer-a518980.md]
- Direct implication for this Bee's LinkedIn Company Page audit specifically: because the underlying visibility mechanism (owner-controlled per-section toggles) is documented at the personal-profile level and no LinkedIn Company-Page-specific override was found in this round's sources, an unauthenticated visit to a Company Page should be expected to show a similarly variable subset of fields rather than a fixed guaranteed set, an inference from the personal-profile mechanics, not a directly sourced Company-Page-specific claim.
- No round-3 source specifically addressed Facebook Page (as opposed to Instagram or LinkedIn) public-visibility mechanics; this remains an open gap, flagged in section 6.

## 3. Data that is publicly visible without authentication (profile and branding layer)

These checks operate on what any visitor, logged in or not, can see on a public profile, and map to work this Bee can do without any per-platform opt-in. Round 2's table is preserved below with round 3's structural confirmation layered on top from section 2.

| Check | Detail | Source |
|---|---|---|
| Account inventory | List every account, active or inactive, across all platforms in use, including newer ones; also search each network for the brand name to surface forgotten, rogue, or imposter accounts | [raw/blog-hootsuite-com-social-media-audit.md] |
| Profile/cover images | Current, on-brand, correctly sized per platform, not pixelated or badly cropped; PostEverywhere gives a specific floor of at least 400x400px for profile photo clarity, attributed to Sprout Social | [raw/blog-hootsuite-com-social-media-audit.md] [raw/posteverywhere-ai-blog-social-media-audit-checklist.md] |

| Bio link destination | Confirm the link actually resolves and points to the intended destination (homepage versus a more specific landing page) | [raw/posteverywhere-ai-blog-social-media-audit-checklist.md] |
| Username consistency | Same handle across platforms where possible, though more than one account per network is acceptable if the accounts serve different purposes | [raw/blog-hootsuite-com-social-media-audit.md] [raw/posteverywhere-ai-blog-social-media-audit-checklist.md] |
| Contact info and links | Phone, email, business address, and website URL correct and current on every platform that supports them | [raw/blog-hootsuite-com-social-media-audit.md] [raw/posteverywhere-ai-blog-social-media-audit-checklist.md] |
| Pinned post relevance | Should be current best-performing content, an active promotion, or an evergreen brand intro; PostEverywhere's staleness threshold is 3 months | [raw/blog-hootsuite-com-social-media-audit.md] [raw/posteverywhere-ai-blog-social-media-audit-checklist.md] |
| Verification status | Whether the account is verified (blue checkmark or equivalent) where verification is available and relevant | [raw/blog-hootsuite-com-social-media-audit.md] [raw/posteverywhere-ai-blog-social-media-audit-checklist.md] |

## 4. Content-performance checks: mixed visibility

- Top-performing and bottom-performing post identification (Hootsuite: list the top five performing posts per platform, archived text cuts off before detailing the bottom-post analysis; PostEverywhere: identify top 5 AND bottom 5 posts by actual engagement rate, calculated as engagements divided by reach times 100, not raw like counts) is content-level analysis that can often be done from what is visible on a public profile's post history, though computing a precise engagement RATE (as opposed to raw like/comment counts visible on the post itself) may depend on reach figures that are only exposed through a platform's own analytics. [raw/blog-hootsuite-com-social-media-audit.md] [raw/posteverywhere-ai-blog-social-media-audit-checklist.md]
- Round 3 confirms this precisely for Instagram: post captions, hashtags, media type/URL, permalink, timestamp, and public like/comment counts are all visible on a public profile without login; engagement RATE (which needs reach, a denominator that is not public) is not computable from the public view alone. [raw/www-getphyllo-com-post-social-media-public-data.md]
- PostEverywhere's fuller content-performance list (Section 2, fully preserved in the archive) includes: content-mix ratio by category (educational/promotional/entertaining/conversational, with an 80/20 value-to-promotion baseline named as common but explicitly flagged as something to verify against the account's own data rather than assume); posting frequency against platform benchmarks; visual quality across the last 30 posts (resolution, video formatting, carousel rendering); caption/copy quality (hook strength, clear calls to action, natural keyword use); hashtag performance (cutting hashtags that do not drive measurable reach); content gaps (topics the audience is asking about that are not yet covered); and content-repurposing opportunities (long-form assets like blog posts, podcasts, or videos not yet broken into social content, with the claim that "most brands leave 80% of their content value on the table"). [raw/posteverywhere-ai-blog-social-media-audit-checklist.md]

## 5. Login-gated data: the specific class this plugin's opt-in flow gates

This is the data class most directly relevant to this Bee's product constraint: it only exists behind a platform's own native analytics or logged-in view, and per this plugin's design, this Bee prompts the user to authenticate per platform to collect it, and silently no-ops (never a score penalty) if the user declines or authentication is unavailable.

- Native analytics metrics, named specifically by PostEverywhere: follower growth rate over the last 90 days (formula given: new followers divided by starting followers, times 100; a stated healthy-account floor is 1 to 3% growth per month minimum, attributed to Hootsuite's own trends reporting); reach trend over the last 90 days (with the specific interpretive claim that if reach is dropping while followers are growing, the algorithm is suppressing the content rather than the content simply underperforming); and impressions-versus-reach ratio (a wide gap meaning the same people are seeing content multiple times). All three are computed from numbers that live inside each platform's own analytics dashboard, not from anything visible on the public-facing profile or post. [raw/posteverywhere-ai-blog-social-media-audit-checklist.md]
- Round 3 sharpens exactly why, for Instagram specifically: impressions, reach, saves, shares, profile visits, and audience demographic breakdown are, per the technical source, released by Meta to the account holder alone, across every surface Meta offers, official or otherwise; there is no login-free substitute, only estimates modelled from public followers/engagement, which the source flags as "fine if labelled, misleading if resold as measured." [raw/www-getphyllo-com-post-social-media-public-data.md]
- Audience demographics: Hootsuite's own 7-step process names "Understand your audience on each platform" as step 6, distinct from and following its content-performance and channel-performance steps, but the archived fetch cuts off before step 6's content is reached, so no specific demographic data point (age, gender, location breakdown, or similar) can be sourced from this archive beyond the step's existence and its position in the process. Audience demographics of this kind are a canonical example of a metric only exposed through a platform's native, logged-in analytics view, which is exactly the data class this plugin's per-platform opt-in prompt is designed to gate, and round 3's Instagram-specific source confirms this pattern directly for that one platform. [raw/blog-hootsuite-com-social-media-audit.md] [raw/www-getphyllo-com-post-social-media-public-data.md]
- Channel-performance evaluation (Hootsuite's step 4) and competitive benchmarking (step 5) are both listed as steps in the same 7-step process but, like step 6, have no surviving descriptive content in the archived fetch; their evaluation likely also draws on native analytics (for channel performance) and third-party or manually-gathered competitor data (for benchmarking), but that inference is not directly sourced and is stated here only as a plausible reading, not a researched fact. [raw/blog-hootsuite-com-social-media-audit.md]
- Compliance and governance review is named as Hootsuite's step 7 with no surviving detail beyond its title. [raw/blog-hootsuite-com-social-media-audit.md]

Practical mapping for this Bee: everything in section 3 above (profile, branding, bio, links, verification, and the round-3-confirmed Instagram fixed-field list and LinkedIn owner-toggled field list) and most of section 4 (post history, visible engagement counts, content mix by inspection) is reachable without authentication and should be scored normally regardless of opt-in status. Everything in this section 5 (native analytics numbers such as follower growth rate, reach trend, impressions-to-reach ratio, and platform-native audience demographics) is the specific data class that requires the per-platform authenticated session; when a user declines that prompt or the harness cannot authenticate, this Bee's own product design (not sourced from any raw file, since none of the five sources discuss opt-in consent flows) calls for a silent no-op on those specific sub-checks rather than scoring them as failing or missing.

## 6. Platform-specific business-profile completeness signals

Round 3 target: what does a complete profile look like per platform, beyond generic "fill in your bio" advice. This section draws only on what survived in the archived fetches; several completeness numbers surfaced in round-3 search-result highlights but were not independently fetched into the raw archive, and are therefore NOT cited as sourced claims here (see the gap note at the end of this section).

- Instagram's fixed always-public field set (name, username, profile picture, bio, links, follower/following counts, avatar, Threads username, channels) is, per Meta's own framing, not something the account owner can hide at all, on public or private accounts alike; this means an Instagram completeness audit is auditing the QUALITY of these fields (is the bio filled in well, is the link current), not their visibility, since visibility is not owner-configurable in the first place. [raw/www-facebook-com-help-347751748650214.md]
- LinkedIn's public-profile completeness signal is structurally different: because visibility of most sections (photo, headline, summary, experience, skills, activity) is owner-toggled, a LinkedIn completeness audit run from an unauthenticated browser view must account for the possibility that a genuinely complete profile is scoring as "incomplete" in the audit simply because the owner has toggled a filled-in section to non-public, versus a genuinely sparse profile. LinkedIn's own guidance is that disabling the public profile entirely removes it from non-member and search-engine visibility altogether, and could even complicate account recovery for the owner, but says nothing about a middle ground of "complete but not fully public." This is a structural audit limitation, not a false-positive bug in this Bee's own logic. [raw/www-linkedin-com-help-linkedin-answer-a518980.md]

## 7. Why audits get run (business framing)

- Cited reasons to run an audit: identifying underperforming channels, learning which content formats drive engagement or conversions, proving ROI to leadership, aligning team effort with company goals, catching branding inconsistencies before they damage trust, and spotting competitive gaps. Two market-scale figures are given as context, not as benchmarks to apply directly: 59% of CMOs reportedly say they lack sufficient budget to execute their strategy, and global social ad spend is cited as reaching $276 billion in 2025. [raw/blog-hootsuite-com-social-media-audit.md]
