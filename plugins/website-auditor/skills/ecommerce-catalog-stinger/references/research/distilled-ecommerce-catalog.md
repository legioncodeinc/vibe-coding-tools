# Distilled ecommerce-catalog research

Dense reference distilled from `raw/`. Every claim below cites its source file in brackets. Organized around this Bee's actual job: a bonus, conditional audit of up to 25 product pages when a commerce platform is detected, split into a quantified metadata-completeness axis and a subjective copy/conversion-quality axis, kept separate per the SKILL's own description.

This is the round-3 rewrite of this file. Coverage was flagged thin after round 2 (2 vendor/community-blog sources only). This pass adds 3 sources: schema.org's own canonical `Product` type page (official docs), an individual technical-SEO practitioner's detailed required-vs-recommended field breakdown (community post, independently corroborating the prior Anglera source), and a DTC-conversion-copywriting vendor blog giving a whole-page structural framework (closing the "features vs benefits, scannability, trust signals" gap named in this pass's brief). 5 raw sources now exist total. ## 2. Quantified metadata-completeness checks (on-page / human-facing)

| Check | Requirement | Source |
|---|---|---|
| Image count | At least 5 images per product (front, back, detail close-up, scale reference, lifestyle) as a floor | [raw/craftshift-com-shopify-product-page-30-point-audit-2026.md] |
| Image source resolution | 2048 x 2048 source dimensions, 100 to 300 KB after compression | [raw/craftshift-com-shopify-product-page-30-point-audit-2026.md] |
| Image size ceiling | Above 5000 x 5000 (a stated 25 MP cap) gets rejected outright by Shopify; 2048 to 4500 is accepted but renders slowly on mobile | [raw/craftshift-com-shopify-product-page-30-point-audit-2026.md] |
| Zoom threshold | Zoom activates only above 800 x 800 source resolution on Shopify; should resolve to 2048+ pixels of detail | [raw/craftshift-com-shopify-product-page-30-point-audit-2026.md] |
| Variant-specific imagery | Each variant (for example each color) should lead the gallery with an image of that specific variant, not the generic cover image; Shopify natively supports one image per variant | [raw/craftshift-com-shopify-product-page-30-point-audit-2026.md] |
| Alt text presence and quality | Every image needs descriptive alt text (example pass: "Navy oversized hoodie front view"; example fail: "IMG_4521" or an empty string); sample 10 images at random, if more than two fail, audit the whole catalog | [raw/craftshift-com-shopify-product-page-30-point-audit-2026.md] |
| Standardized spec fields | Material, dimensions, weight, and country of origin should live in Shopify metafields (or the theme's spec fields), not free text, because both AI agents and Google Shopping read structured fields | [raw/craftshift-com-shopify-product-page-30-point-audit-2026.md] |
| Media aspect-ratio coverage | Google recommends including images across the 1:1, 4:3, and 16:9 range within the `image` array | [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md] |
| Meta tag uniqueness | Unique title tag and meta description per product; not templated so tightly that every variant reads identically | [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md] |
| Canonical tag | Self-referencing canonical defined in the original HTML, not injected only by JavaScript | [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md] |
| Core Web Vitals thresholds | Largest Contentful Paint under 2.5s, Interaction to Next Paint under 200ms, Cumulative Layout Shift under 0.1 (cited as still Google's current bar for good page experience) | [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md] |
| Identifier consistency | The same identifier values should match across the PIM/source of truth, the on-page JSON-LD, and any feed (Merchant Center, marketplace, affiliate); mismatches are named as a common cause of "incorrect identifier" flags | [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md] |

## 3. Structured-data (schema.org Product / Google) required vs. recommended fields

This section is substantially expanded in this pass; round 2 had only Anglera's single "name plus one of offers/review/aggregateRating" rule with no fuller required/recommended breakdown. Two independent sources now corroborate a fuller, surface-specific split.

- Google splits Product markup eligibility into two distinct experiences that share the same `schema.org/Product` vocabulary: **product snippets** (non-transactional or general product pages, lighter requirements, emphasizing reviews and price) and **merchant listings** (pages where the product can actually be bought, stricter requirements, emphasizing full shopping detail: price, availability, shipping, returns). Passing generic schema.org vocabulary validation does NOT by itself establish either eligibility; that is a separate check against Google's own documentation/tools. [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md]
- Product-level required vs. recommended, by surface (corroborated identically by both sources where they overlap):

| Property | Product snippet | Merchant listing | Source |
|---|---|---|---|
| `name` | Required | Required | [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] |
| `image` | Recommended | Required | [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] |
| `offers` | One of offers/review/aggregateRating required | Required outright, no either/or | [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md] |
| `description` | Recommended | Recommended | [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] |
| `sku` | Recommended | Recommended | [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md] |
| `gtin` / `mpn` | Recommended | Recommended | [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md] |
| `brand` | Recommended | Recommended (`brand.name`, nested object) | [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md] |
| `aggregateRating` | Recommended | Recommended | [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] |
| `review` | Recommended | Recommended | [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] |

- Offer-level required vs. recommended, by surface:

| Property | Product snippet | Merchant listing | Source |
|---|---|---|---|
| `price` | Required (0 allowed for free items) | Required (must be > 0) | [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] |
| `priceCurrency` | Recommended | Required | [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] |
| `availability` | Recommended | Recommended | [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] |
| `priceValidUntil` | Recommended | Recommended | [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] |
| `itemCondition` | Recommended | Recommended | [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] |
| `hasMerchantReturnPolicy` | Not listed for this surface | Recommended | [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] |
| `shippingDetails` | Not listed for this surface | Recommended | [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] |
| `url` | Recommended | Recommended | [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] |

- Two rules flagged by patrickstox.com as most commonly missed in practice: for merchant listings specifically, price must be greater than zero (product snippets tolerate a `0` price for free items); and `priceCurrency` is required for merchant listings but only "currently recommended" for basic product snippets. [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md]
- Scoping rule (quoted from Google via patrickstox.com): "product rich results only support pages that focus on a single product (or multiple variants of the same product)." A category/listing page marked up as one `Product` is invalid; for a genuine line of variants, use `ProductGroup` markup instead of one `Product` block per page. [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md] This corroborates and sharpens the pre-existing `isVariantOf`/`ProductGroup` guidance from Anglera. [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md]
- schema.org's own `Product` type page defines the underlying vocabulary these required/recommended tables draw from, including fields neither vendor source discussed in the same depth: `gtin` (generalizes `gtin8`/`gtin12`/`gtin13`/`gtin14`, must be a validly-checksummed all-numeric string or a GS1 Digital Link URL, left-padding not required or encouraged), `colorSwatch` (an image or ImageObject visualizing the `color` property's value, should match it), `hasCertification`, `hasEnergyConsumptionDetails`, `countryOfOrigin` / `countryOfAssembly` / `countryOfLastProcessing`, and `additionalProperty` (a `PropertyValue` pair mechanism explicitly flagged as a fallback: publishers should prefer a dedicated schema.org property like `color` or `gtin13` over the generic property/value mechanism when one exists). [raw/schema-org-product.md]
- Authority note: schema.org's page is the canonical vocabulary source and should be treated as authoritative for what a field MEANS and what type it expects; it is not authoritative for what Google (or any other single consumer) REQUIRES for a specific rich-result feature; that eligibility layer is patrickstox.com's and Anglera's territory, and both are consistent with each other on it. [raw/schema-org-product.md] [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md]

## 4. Subjective copy/conversion-quality checks

- Product title should contain the buyer's likely search term rather than an internal brand name; the given example contrasts an internal name ("Sarah Bra") with what a customer actually searches ("Sarah High-Support Sports Bra"), pairing brand, category, and key attribute. [raw/craftshift-com-shopify-product-page-30-point-audit-2026.md]
- Description should lead with concrete specifications (materials, dimensions, key features) rather than marketing language; the given contrast is "40L waterproof hiking backpack with laptop compartment" (passes) versus "Adventure Day Pack" (fails), on the reasoning that both human readers and AI agents lose the marketing-fluff opener. Personality copy can follow the specs, not precede them. [raw/craftshift-com-shopify-product-page-30-point-audit-2026.md]
- Returns, shipping, and care information should be visible on the product page itself (expandable section or accordion is acceptable), on the stated reasoning that customers want this before purchase, not after, and that surfacing it raises conversion and reduces support tickets. [raw/craftshift-com-shopify-product-page-30-point-audit-2026.md]
- Variant picker UX: color should be presented as visual swatches, not a text dropdown, described as reducing clicks, improving mobile UX, and outperforming dropdowns on conversion "in nearly every measured study" (no specific study is cited in the archived text, so treat this as the source's own summary claim, not a sourced statistic). [raw/craftshift-com-shopify-product-page-30-point-audit-2026.md]
- Swatch color fidelity: a named color (for example "Forest Green") should render as the true hex of the actual product color, not a generic CSS-named color, mapped per custom color name. [raw/craftshift-com-shopify-product-page-30-point-audit-2026.md]
- Out-of-stock handling: sold-out variants should be either struck through or fully hidden, either is acceptable, but an ambiguous treatment (greyed with no strikethrough or indicator) is called out as confusing; a theme that auto-selects a sold-out variant by default is flagged as an immediate-fix issue since the customer lands on a dead Add to Cart. [raw/craftshift-com-shopify-product-page-30-point-audit-2026.md]
- Size/fit guidance (chart or fit recommender, in a modal, expandable section, or inline) is recommended for apparel, footwear, and accessories specifically, on the claim that it measurably reduces returns and improves first-visit conversion. [raw/craftshift-com-shopify-product-page-30-point-audit-2026.md]

### Whole-page conversion architecture (new in this pass, closes the "features vs benefits, scannability, trust signals" gap)

DTCskills gives a 9-section, sequenced page architecture, framed as mirroring a buyer's decision process from attention to trust to action, one level up from a single feature-to-benefit sentence: [raw/dtcskills-com-blog-shopify-product-page-copywriting.md]

| # | Section | Job | Notes |
|---|---|---|---|
| 1 | Hook | Stop the scroll in the first five seconds; name the problem/outcome, not the product | Example contrast given: "Premium Magnesium Glycinate, 120 Capsules" (weak) vs. "Stop Waking Up at 3am. Fall Asleep Faster and Stay Asleep." (strong) |
| 2 | Social Proof (first touch) | Establish credibility before the pitch; star rating + review count + one short quote | Placed directly below the hook, before the description |
| 3 | Feature-Benefit Bridges | Translate each feature via a "which means" / "so you can" bridge to an outcome | 3 to 5 bridges recommended as the sweet spot; more buries the lead; pick the features that address the biggest objections |
| 4 | Mechanism | Explain, in plain language, why the product works differently than alternatives | Builds credibility and differentiation; gives the buyer a reason they can repeat to someone else |
| 5 | Objection Handling | Address the 3-5 reasons people do not buy | Objections should be sourced from support inbox, low-star reviews, and abandoned-cart survey responses, not guessed |
| 6 | Authority | (named in the framework; full detail not captured in the archived fetch) | Gap: see section 6 below |
| 7 | Secondary Social Proof | The full review section: photos, verified-purchase badges, specific result quotes | Distinct from Section 2's single-quote first touch |
| 8 | Risk Reversal | (named in the framework; full detail not captured in the archived fetch) | Gap: see section 6 below |
| 9 | CTA | Price, bundle savings, one-line value recap, one primary button | Recommendation: keep it clean, one primary action |

Buyer-awareness mapping given by the source: cold traffic is hooked by Section 1 and educated by Sections 3-5; warm traffic skips to Sections 5-7 for proof and reassurance; hot traffic scrolls straight to Section 9. [raw/dtcskills-com-blog-shopify-product-page-copywriting.md]

This framework is Shopify-DTC-specific in its worked example (a supplements brand) and assumes a single-hero-product page layout; it should be read as a structural pattern to check for (is there a hook, is there objection handling, is trust signaled at two distinct points) rather than a template requiring all nine named sections verbatim on every product page this Bee audits, since the plugin's scope spans arbitrary storefronts and categories, not only DTC-style Shopify pages. [raw/dtcskills-com-blog-shopify-product-page-copywriting.md]

## 5. Technical/agent-readability layer (distinct axis from both metadata completeness and copy quality)

- Rendering: most AI crawlers, named specifically as GPTBot, ClaudeBot, Claude-User, Claude-SearchBot, and PerplexityBot, fetch raw HTML and generally do not execute JavaScript or run a rendering pass. If enriched attributes, specs, or use-case copy only appear after a client-side fetch resolves, these agents see an empty shell. Google itself still uses a two-wave system (raw HTML crawled first, a second headless-Chromium render pass queued afterward, sometimes hours or days later), and server-side rendering/static generation/hydration remain its recommended pattern over pure client-side rendering. [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md]
- Verification method given: check with `view-source:` or `curl` rather than trusting DevTools, since DevTools always shows the post-render DOM, not what a non-executing crawler actually receives. [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md]
- Structured-data integrity rule: markup must reflect what is genuinely visible on the page, not content hidden behind toggles, absent from the DOM, or fabricated to win a rich result; if a field exists only in a feed and never on the rendered page, it should be left out of the JSON-LD. [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md] patrickstox.com's own validation guidance corroborates this from the Google-eligibility side: price, availability, and name in the JSON-LD must agree with what a shopper actually sees, and mismatches must also be checked against a Merchant Center feed and the actual checkout, since these are three separately reconciled systems, not one validation pass. [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md]
- Variant grouping in structured data: for products sold in multiple sizes/colors/configurations, use the `isVariantOf`/`ProductGroup` pattern rather than duplicating one `Product` block per variant on a single URL; variants need their own URLs or the group pattern to stay compliant. [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md] [raw/patrickstox-com-technical-seo-on-page-structured-data-commerce-product-schema.md]
- Attributes belong in the visible DOM (a definition list, table, or labeled grid), not only inside JSON-LD or an alt attribute; `additionalProperty`/`PropertyValue` pairs can carry structured attribute data in JSON-LD, but the source is explicit this is only valid alongside a visible on-page version, not as a replacement for one. This is corroborated by schema.org's own note on `additionalProperty`, which flags it as a fallback mechanism to use only when no dedicated property already exists for the characteristic being described. [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md] [raw/schema-org-product.md]
- Media detail: avoid `loading="lazy"` on the primary hero image specifically, since it can delay Largest Contentful Paint measurement and, in edge cases, keep the image out of a lightweight-fetch snapshot. [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md]
- Localization: multi-currency or localized PDPs should use distinct URLs per locale/currency with correct `hreflang`, matching Google's guidance that Product markup should not mix currencies on one URL. [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md]
- Performance offenders named specifically for PDPs: render-blocking third-party scripts above the fold (reviews widgets, chat, personalization) and layout shift from images or price blocks loading without reserved space; the fix given is reserving height for images and dynamic price elements (the archived text cuts off mid-sentence on this last point). [raw/www-anglera-com-blog-enriched-data-to-page-checklist.md]

## 6. Combined-listing and separate-product-per-color patterns

- Where separate colorways exist as separate Shopify products (the example given: "Sarah Bra Black" and "Sarah Bra Olive" as distinct products), the checklist recommends linking them as one shoppable group, on the stated claim that this improves both human UX and AI-agent surfacing of the full color range; a named app (Rubik Combined Listings) is cited as one way to do this on Shopify specifically. [raw/craftshift-com-shopify-product-page-30-point-audit-2026.md]
- Default-variant selection: Shopify's `product.selected_or_first_available_variant` Liquid object returns the first in-stock variant, but some themes use `product.variants[0]` instead, which can land a customer on a sold-out variant by default; the fix is checking the theme's Liquid and switching to the first-available form. This is Shopify-template-specific and does not generalize to other commerce platforms without verification against that platform's own equivalent. [raw/craftshift-com-shopify-product-page-30-point-audit-2026.md]
