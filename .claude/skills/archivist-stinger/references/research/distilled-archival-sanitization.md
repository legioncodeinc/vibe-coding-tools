# Distilled research: sanitizing and archiving an acquired repository

Stage 3 of the forge pipeline for `archivist-stinger`. Every claim below ends with a citation into `raw/`. Sources were fetched 2026-09-05. Where two sources read differently the table in section 7 states both and the preferred official reading. Where coverage is thin, section 7 says so; nothing here is filled from training data.

Reading order: section 1 (what "license and attribution" physically look like in a repository) grounds the inventory; section 2 (manifest fields per ecosystem) grounds the language-agnostic sweep; sections 3 and 4 ground the PII and history decisions; section 5 grounds the archival record; section 6 maps every finding onto a procedure rule.

## 1. Where license and copyright information lives

| Convention | What it defines | Archivist reading | Source |
| --- | --- | --- | --- |
| SPDX License List | A curated list of licenses and exceptions, each with a standardized short identifier, full name, text, and canonical URL; list version 3.28.0 dated 2026-02-20 at fetch time | Every license the inventory finds should be recorded as an SPDX identifier or a `LicenseRef-` custom id, so the intake manifest is unambiguous | [raw/licensing--spdx--license-list.md] |
| SPDX short-form identifier | One comment line per file, `SPDX-License-Identifier: <expression>`, with expressions built from `AND`, `OR`, `WITH`, the `+` suffix for later versions of non-GNU licenses, and `-only` or `-or-later` suffixes for GNU licenses | Grep for `SPDX-License-Identifier` is a complete, language-independent way to find per-file license tags | [raw/licensing--spdx--handling-license-info.md] |
| SPDX and copyright notices | "Copyright notices ... are outside the scope of SPDX short-form IDs. Therefore, you should not remove or modify existing copyright notices in files when adding an SPDX ID." | A file can carry a license tag and a separate copyright line; the sweep treats them as two signals with two decisions | [raw/licensing--spdx--handling-license-info.md] |
| REUSE 3.3, licensing information | Every Covered File MUST have licensing information via a comment header (recommended), a `REUSE.toml` annotation, or the deprecated `.reuse/dep5`; uncommentable files use an adjacent `<name>.license` sidecar; snippets use `SPDX-SnippetBegin` and `SPDX-SnippetEnd` | The inventory must read headers, sidecars, `REUSE.toml`, and `.reuse/dep5`, not only the root license file | [raw/licensing--reuse--spec-3-3.md] |
| REUSE 3.3, copyright notice format | A notice starts with `SPDX-FileCopyrightText`, `Copyright`, or `©`, MUST contain the holder's name, SHOULD contain the year and a contact address in angle brackets | A REUSE-compliant repository puts the seller's name and often email into every file header; the scrub must cover headers, not just root files | [raw/licensing--reuse--spec-3-3.md] |
| REUSE 3.3, license files | A `LICENSES/` directory holding one file per license named by SPDX identifier; `COPYING`, `LICENSE`, `LICENCE` (optionally with a dash or dot suffix such as `LICENSE-MIT` or `COPYING.GPL`) MAY exist for other tools and are ignored by the REUSE tool | `LICENSES/` often contains licenses of third-party components; each file there needs an owner decision, not a blanket delete | [raw/licensing--reuse--spec-3-3.md] |
| REUSE 3.3, ignored files | VCS metadata, gitignored files, submodules, symlinks, zero-byte files, and SPDX documents are not Covered Files | Sanitization scope can mirror this list: gitignored and generated content is outside the notice inventory | [raw/licensing--reuse--spec-3-3.md] |
| REUSE 3.3, `REUSE-IgnoreStart` | Licensing information that is not a real notice (for example, inside a script that prints notices) is wrapped in `REUSE-IgnoreStart` and `REUSE-IgnoreEnd` | Expect false positives from strings that print or test notices; the sweep reports them for review rather than editing them | [raw/licensing--reuse--spec-3-3.md] |
| GitHub license placement and detection | Most projects put the text in `LICENSE.txt`, `LICENSE.md`, or `LICENSE.rst` at the root; some note the license in the README; detection compares the root file against a short list of known licenses (licensee); a file with multiple licenses or extra text is not detected | Root file names to inventory: `LICENSE*`, `COPYING*`, `LICENCE*`; also grep READMEs for license statements | [raw/licensing--github--licensing-a-repository.md] |
| No license means all rights reserved | "without a license, the default copyright laws apply, meaning that you retain all rights to your source code and no one may reproduce, distribute, or create derivative works" | Removing every license from an acquired repository leaves it all-rights-reserved to the acquirer, which is the intended archival state | [raw/licensing--github--licensing-a-repository.md] |
| Public repositories and forks | Other GitHub users may view and fork a public repository; making it private later does not remove existing forks or local copies | A scrub of the working tree does not reach forks of the seller's original repository; the intake records this as out of scope | [raw/licensing--github--licensing-a-repository.md] |
| OpenChain ISO/IEC 5230 | "defines the key requirements of a quality Open Source License Compliance Program" and "identifies the key places to have license compliance processes, how to assign roles and responsibilities, and how to ensure sustainability" | Frames the archivist's inventory as a compliance artifact; the requirement text itself is not in this archive (section 7) | [raw/licensing--openchain--iso-5230.md, raw/licensing--openchain--spec-repo-readme.md] |
| ORT (OSS Review Toolkit) | Analyzer, downloader, scanner, advisor, evaluator, reporter, notifier; the reporter emits NOTICE files in two variants (license texts and copyrights per package, or a summary), SPDX documents, and CycloneDX BOMs | Third-party notice generation is solved tooling; the archivist preserves existing notices and may use ORT or ScanCode to inventory them, never hand-writes them | [raw/licensing--ort--notices-and-third-party.md, raw/licensing--ort--reporter.md] |
| ScanCode Toolkit | Detects origin (copyrights), license, vulnerabilities, package manifests, and direct dependencies in source and binary files; language-independent; outputs JSON, YAML, HTML, CycloneDX, SPDX; can generate an attribution document from a scan; its own NOTICE and `.ABOUT` files document third-party origin | A scanner run is the thorough version of `attribution_sweep.py`; use it when the repository is large or polyglot | [raw/licensing--scancode--readme.md, raw/licensing--scancode--what-it-detects.md] |

## 2. Identity, license, and origin fields in package manifests

The sweep is language-agnostic because every ecosystem exposes the same three families of fields: people (author, maintainers, contributors, owners, developers), license (identifier or expression, license file paths), and origin links (repository, homepage, bugs, funding, support). The table lists the exact keys per ecosystem so the intake can read them mechanically.

| Ecosystem and manifest | People fields | License fields | Origin and link fields | Notes | Source |
| --- | --- | --- | --- | --- | --- |
| npm `package.json` | `author` (one person: `name`, optional `url`, `email`), `contributors` (array of people) | `license` | `repository`, `homepage`, `bugs` (URL and/or email), `funding` (URL, object, or array) | `bugs` may carry an email address | [raw/ecosystems--npm--package-json.md] |
| Python `pyproject.toml` `[project]` | `authors`, `maintainers` (lists of `name` and/or `email`) | `license` (SPDX expression string per PEP 639; the table form is deprecated), `license-files` (globs such as `LICEN[CS]E*`, `AUTHORS*`) | `urls` table (Homepage, Documentation, Repository, Issues, Changelog) | `license-files` can pull `AUTHORS*` files into the distribution | [raw/ecosystems--python--pyproject-toml.md] |
| Python core metadata (PEP 639) | n/a | `License-Expression` (SPDX), `License-File` (multi-use paths, which "could include license text, author/attribution information, or other legal notices"); the legacy `License` field and license classifiers are deprecated and mutually exclusive with `License-Expression` | n/a | Built wheels and sdists carry these fields even after the source manifest is scrubbed; rebuild after scrubbing | [raw/ecosystems--python--pep-639.md] |
| Rust `Cargo.toml` `[package]` | `authors` (deprecated, still surfaced in metadata and `CARGO_PKG_AUTHORS`) | `license` (SPDX expression with `OR`, `AND`, `WITH`), `license-file` (path); crates.io requires one of them | `repository`, `homepage`, `documentation`; `[package.metadata]` free-form for external tools | A deprecated field still ships; remove it rather than assume it is dead | [raw/ecosystems--rust--cargo-manifest.md] |
| Java Maven `pom.xml` | `developers`, `contributors` (same elements minus `id`), `organization` | `licenses` (project's own only, "not licenses that apply to the project's dependencies"; SPDX identifier recommended as `name`) | `scm`, `url`, `issueManagement` | Maven's own guidance separates first-party from dependency licenses, the same split the intake applies | [raw/ecosystems--java--maven-pom.md] |
| Ruby `.gemspec` | `authors` (or singular `author`), `email` | `license` or `licenses` | `homepage`, `metadata` (string hash carrying `source_code_uri`, `bug_tracker_uri`, and similar) | `email` is a direct contact address on the gem | [raw/ecosystems--ruby--gemspec-reference.md] |
| PHP `composer.json` | `authors` (array of objects) | `license` (string or array) | `homepage`, `support`, `funding` (list of URLs) | | [raw/ecosystems--php--composer-schema.md] |
| .NET `.nuspec` `<metadata>` | `authors` (required, comma-separated; ignored for ownership on nuget.org), `owners` (deprecated) | `license` (SPDX expression or file, NuGet 4.9+), `licenseUrl` (deprecated) | `projectUrl`, `repository` (`type`, `url`, `branch`, `commit`), `copyright` (free text) | `copyright` is a dedicated attribution field | [raw/ecosystems--dotnet--nuspec-reference.md] |
| Go `go.mod` | none | none | none; the module path itself (for example a forge URL with an owner segment) is the identity | Go carries origin in the module path and in `go.sum` entries, not in fields; renaming a module path is a code change, not a metadata edit | [raw/ecosystems--go--go-mod-reference.md] |

## 3. Personal data, pseudonymisation, and detection

| Finding | Archivist reading | Source |
| --- | --- | --- |
| UK GDPR Article 4(5): pseudonymisation is "processing of personal data in such a manner that the personal data can no longer be attributed to a specific data subject without the use of additional information, provided that such additional information is kept separately" | Replacing names with placeholders in the tree while the intake manifest (kept outside the repository) records who they were is pseudonymisation of the archive, not anonymisation | [raw/identity--ico--pseudonymisation-guidance.md] |
| "Pseudonymised data is personal data in the hands of someone who holds the additional information"; Recital 26 treats data attributable via additional information as information on an identifiable person; shared without the key, it "may be anonymous information in their hands" | The archive alone, without the intake manifest, is what downstream research consumers receive; keep the manifest out of the repository and out of the archive bundle | [raw/identity--ico--pseudonymisation-guidance.md] |
| Pseudonymisation is a risk-reduction and security measure, not a way to take data outside the law, and it supports research reuse | Frames the purpose of the scrub honestly: it reduces exposure; it does not create a legal fiction | [raw/identity--ico--pseudonymisation-guidance.md] |
| EDPB Guidelines 01/2025 on pseudonymisation (executive summary and definitions extracted from the published PDF) | Corroborates the definition above at EU level; consult the raw file for the EDPB wording before citing it in a report | [raw/identity--edpb--pseudonymisation-guidelines.md] |
| GitHub `noreply` addresses take the form `ID+USERNAME@users.noreply.github.com` (accounts created after 2017-07-18) or `USERNAME@users.noreply.github.com` (older accounts with privacy enabled) | A noreply address is still an identifier: it contains the username and, in the newer form, the account id. Treat it as PII in commit metadata and in any file that quotes it | [raw/identity--github--email-addresses-reference.md, raw/identity--github--commit-email-noreply.md] |
| Presidio: an analyzer identifies entities with NER, regular expressions, rule logic, and checksums with context; an anonymizer applies operators; predefined global entities include PERSON, EMAIL_ADDRESS, PHONE_NUMBER, LOCATION, IP_ADDRESS, MAC_ADDRESS, URL, CREDIT_CARD, IBAN_CODE, CRYPTO, DATE_TIME, NRP, MEDICAL_LICENSE, plus country-specific identifiers | Names the entity classes a repository sweep should at least consider beyond emails and handles: phone numbers, IPs, MACs, and full names in prose, fixtures, and logs | [raw/identity--presidio--supported-entities.md, raw/identity--presidio--overview.md] |
| Presidio's own warning: "there is no guarantee that Presidio will find all sensitive information. Consequently, additional systems and protections should be employed." | Automated detection is a floor; a human review of the sweep report is part of the procedure, and a second sweep after edits is mandatory | [raw/identity--presidio--overview.md] |
| gitleaks: `gitleaks git [-v] [--log-opts=...] <repo>` scans history, `gitleaks dir <path>` scans files, `gitleaks stdin` scans a stream; `detect` and `protect` are deprecated since v8.19.0; config precedence is `--config`, `GITLEAKS_CONFIG`, `GITLEAKS_CONFIG_TOML`, a `.gitleaks.toml` in the target, then defaults; a baseline report suppresses known findings; `.gitleaksignore` and inline `gitleaks:allow` comments suppress specific ones | Secrets are a separate class from attribution: run a secrets scanner over history as well as the working tree, because a secret removed from the tree survives in earlier commits | [raw/identity--gitleaks--readme.md] |
| TruffleHog: `trufflehog git <url or path> --results=verified` (add `--json` or `--sarif`), `trufflehog github --org=<org>`; it classifies 800+ secret types and can verify whether a credential is live | Prefer verified results when triaging; an unverified match still needs a look because rotation, not just deletion, is the fix for a live secret | [raw/identity--trufflehog--readme.md] |

## 4. Rewriting git history

| Finding | Archivist reading | Source |
| --- | --- | --- |
| `.mailmap` maps author and committer names and emails to canonical values; four forms: `Proper Name <commit@email>`, `<proper@email> <commit@email>`, `Proper Name <proper@email> <commit@email>`, and `Proper Name <proper@email> Commit Name <commit@email>`; matching is case-insensitive; the file lives at the top level or at `mailmap.file` or `mailmap.blob` | A mailmap alone changes how history is displayed, not what is stored; it is the non-destructive option when the acquirer wants identities hidden from `git log` output without rewriting commits | [raw/identity--git--gitmailmap.md] |
| `git filter-repo --mailmap <file>` rewrites author, committer, and tagger names and emails using the file's current contents; `--use-mailmap` reads `.mailmap`; `--replace-text <file>` replaces expressions (literal by default, `regex:` and `glob:` prefixes, `==>` to choose the replacement, default `***REMOVED***`); `--path` and `--invert-paths` remove files from all history; `--name-callback` and `--email-callback` take Python bodies | The rewrite toolkit for the case where the acquirer approves destroying the original identities in history | [raw/identity--git--filter-repo-manual.md] |
| filter-repo refuses to run outside a fresh clone unless `--force`; the rewrite is irreversible and by default prunes reflogs and old objects; recommending `--force` casually is warned against | Always rewrite in a fresh clone; treat `--force` as a red flag in any procedure | [raw/identity--git--filter-repo-manual.md] |
| GitHub's procedure: rotate any secret first, because rotation may make the rewrite unnecessary; then rewrite locally, update the remote, coordinate every clone, and prevent repeats; `--sensitive-data-removal` requires filter-repo 2.47 or newer; push with `git push --force --mirror origin`; `refs/pull/*` are read-only and must be handled by Support | The archive case is simpler (one owner, no collaborators) but the same order applies: secrets first, fresh clone, mirror push | [raw/identity--github--removing-sensitive-data.md] |
| Side effects listed by GitHub: recontamination when a stale clone pushes, lost work on unrewritten branches, branch protection must be lifted, closed PR diffs break, open PRs desync, commit and tag signatures are removed, and the divergence itself points readers at the old data; data persists in clones, forks, cached views, and PR refs | A history rewrite of a repository that ever had forks does not remove the data from the world; the intake must say so, and the report must not claim otherwise | [raw/identity--github--removing-sensitive-data.md] |

## 5. Archival identifiers

| Finding | Archivist reading | Source |
| --- | --- | --- |
| SWHID: `swh:1:<type>:<hash>` with an optional qualifier list; object types are contents, directories, revisions, releases, and snapshots; hashes are intrinsic, cryptographic, and form a Merkle DAG; identifiers are not URLs, though resolvers exist | The archive record should carry a directory-level identifier for the sanitized tree; the tamper baseline manifest is the lightweight local equivalent, and a SWHID can be computed later without the original repository | [raw/archival--software-heritage--swhid.md] |

## 6. What the research decides for the procedure

| Procedure rule | Grounded in |
| --- | --- |
| Inventory notices in root files (`LICENSE*`, `COPYING*`, `LICENCE*`, `NOTICE*`), `LICENSES/`, per-file headers, `.license` sidecars, `REUSE.toml`, `.reuse/dep5`, READMEs, and every manifest field in section 2 | Section 1 (REUSE, SPDX, GitHub), section 2 |
| Record every license as an SPDX identifier or `LicenseRef-` id in the intake manifest | Section 1 (SPDX License List) |
| Treat a copyright line and a license tag in the same file as two separate decisions | Section 1 (SPDX and copyright notices) |
| Strip only first-party notices; preserve third-party notices verbatim; Maven's own guidance already separates the two | Section 1, section 2 (Maven) |
| Read deprecated fields too (`authors` in Cargo, `owners` in nuspec, `License` and classifiers in Python metadata); deprecated is not absent | Section 2 |
| Rebuild distributable artifacts after scrubbing the source manifest, because built metadata copies the fields | Section 2 (PEP 639) |
| Treat noreply forge addresses as identifiers | Section 3 (GitHub noreply forms) |
| Run a secrets scanner over history, not only the tree, and rotate before deleting | Section 3 (gitleaks, TruffleHog), section 4 (GitHub) |
| Automated detection is a floor: a human reviews the sweep report and a second sweep runs after edits | Section 3 (Presidio warning) |
| Keep the intake manifest outside the repository; the archive without it is pseudonymised, with it the data is still personal | Section 3 (ICO) |
| History: default to leaving it; offer mailmap display mapping; rewrite with filter-repo only on explicit approval, in a fresh clone, never with `--force` as a habit; state that forks and caches are unreachable | Section 4 |
| Record a tree identifier (baseline manifest now, SWHID when archived) so the sanitized state is checkable later | Section 5 |
