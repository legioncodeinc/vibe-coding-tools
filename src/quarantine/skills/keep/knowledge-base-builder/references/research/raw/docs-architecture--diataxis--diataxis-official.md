# Diataxis: the four documentation modes

- **Title:** Start here / Diataxis in five minutes
- **URL:** https://diataxis.fr/start-here/
- **Fetched:** 2026-08-17
- **Source type:** official-docs (the framework's own canonical site, by Daniele Procida)

## The four modes

| Mode | Definition as stated on the site | Serves |
|---|---|---|
| Tutorial | "A tutorial is a lesson, that takes a student by the hand through a learning experience." | Learning by doing, skill acquisition |
| How-to guide | "A how-to guide addresses a real-world goal or problem, by providing practical directions to help the user who is in that situation." | A competent user doing actual work |
| Reference | "Reference guides contain the technical description - facts - that a user needs in order to do things correctly." | Neutral propositional knowledge, structured to mirror the thing described |
| Explanation | "Explanatory guides provide context and background." | Understanding, the reasoning behind things, study rather than work |

## The two generative axes

The four modes are not an arbitrary list. They fall out of two axes:

1. **Action versus cognition.** Tutorials and how-to guides inform action. Reference and
   explanation inform knowledge.
2. **Acquisition versus application.** Tutorials and explanation serve skill acquisition.
   How-to guides and reference serve the application of existing competence.

Crossing the two axes produces the compass that assigns any given piece of content to
exactly one of the four modes.

## The failure mode the framework exists to name

"Crossing or blurring the boundaries described in the map is at the heart of a vast number
of problems in documentation."

The named example: overloading a tutorial with explanation, which undermines the tutorial's
purpose because the learner is trying to act, not to study.

## How the site says to apply it

Explicitly incremental and anti-ideological. The prescribed loop: consider what you have,
ask whether any one thing could be improved, decide on one thing, do that thing, repeat.
No big-bang restructure is required for the framework to pay off.

## Relevance to a knowledge pack

Diataxis is written for user-facing product documentation. A project knowledge pack is a
different genre, and the site does not claim otherwise. What transfers is the boundary
rule: one document, one mode. A file that mixes a requirement, its rationale, and the
history of the argument is the blurring failure the framework names.
