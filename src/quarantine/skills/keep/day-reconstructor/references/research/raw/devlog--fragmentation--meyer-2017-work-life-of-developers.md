## Study design

- **Participants:** 20 professional software developers.
- **Duration:** 2 to 3 work weeks each.
- **Instrument:** an automated logging application recording computer interaction,
  including which programs were used and user input activity.
- **Self-report component:** participants rated perceived productivity every 90 minutes.
  So this study has both logged activity and self-report from the same people at the same
  time.

## Activity breakdown

| Activity | Share |
|---|---|
| Development activities (coding, testing, debugging) | about 30% |
| Email | 15% |
| Work-related web browsing | 11% |
| Meetings | 10% |
| Non-work web browsing | 6% |
| Other | remainder |

## Fragmentation, the load-bearing number

Developers stayed in an individual activity for only **0.3 to 2.0 minutes** before
switching to another. This is the study's core finding about the shape of a workday: work
is not a small number of long blocks, it is a very large number of very short ones.

## Perceived productivity against logged activity

The study relates the logged signal to the self-rated one:

- More user input is most often associated with a positive productivity perception.
- Email, planned meetings, and work-unrelated websites correlate with negative productivity
  ratings.
- Productivity patterns varied substantially between individuals. Three dominant patterns
  appeared: developers most productive in the morning, developers most productive in the
  afternoon, and developers with a midday dip.

The individual variation is directly relevant to a nocturnal user: there is no single
correct productive window, and a tool that assumes one is assuming wrong for a large share
of people.
