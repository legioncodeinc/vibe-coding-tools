# What do developers search for on the web?

- **URL:** https://link.springer.com/article/10.1007/s10664-017-9514-4
- **Fetched:** 2026-08-17
- **Source type:** academic (Empirical Software Engineering, Springer)
- **Why archived:** Establishes what developers actually go to the web for, which is the
  demand side of a personal troubleshooting knowledge base. If the most frequent searches
  are error messages and unknown terminology, then the retrieval key for a personal entry
  has to be the error message, not a topic label.

## Method

Two instruments combined:

- Search query collection from **60 developers**.
- Survey of **235 software engineers** from 21 or more countries across five continents.

34 search tasks were evaluated across the taxonomy below.

## Taxonomy of developer search tasks (seven dimensions)

1. General search
2. Debugging and bug fixing
3. Programming
4. Third-party code reuse
5. Tools
6. Database
7. Testing

## Most frequent search tasks

- Explanations for unknown terminologies
- Explanations for exceptions and error messages, the paper's own example being HTTP 404
- Reusable code snippets
- Solutions to common programming bugs
- Suitable third-party libraries and services

## Most difficult search tasks

Ranked by developer-reported difficulty:

- Solutions to performance bugs
- Solutions to multi-threading bugs
- Public datasets for testing algorithms
- Reusable code snippets
- Best industrial practices
- Database optimization solutions
- Solutions to security bugs
- Solutions to software configuration bugs

## Stated contribution

The abstract states the study "sheds light as to why practitioners often perform some of
these tasks and why they find some of them to be challenging."

## What this source does NOT supply

No figure for how often a developer re-searches something they already solved. The
accessible content carries no per-task percentages. Treat the ordering above as ordinal,
not as measured frequency.
