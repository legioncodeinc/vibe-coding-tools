## Extracted content

**What it is.** The source defines a swipe file as a "mechanics library, not a copy bank",
and states the core principle: "A swipe file should teach you how an asset works. It
should not become a folder of posts to copy."

**Three-tag minimum.** Every captured item is tagged on at least three axes:

1. Hook type (question, bold claim, number, mistake, before-after)
2. Format (carousel, single image, short-form video, text post)
3. Audience problem, tied to a specific journey stage

Broad tags like "How to grow on Instagram" are discouraged. Precise ones like "How to get
saves when you have a small following" are preferred.

**Six metadata fields per captured item.**

| Field | Values named |
|---|---|
| Hook type | mistake, result, confession, checklist, contrarian claim, question, comparison |
| Audience problem | the specific pain addressed |
| Structure pattern | step-by-step, before/after, teardown, myth-versus-truth, FAQ, case story |
| Proof method | example, screenshot, quote, source, personal experience, data, demonstration |
| Visual pattern | layout hierarchy, contrast, density, slide pacing |
| CTA type | comment, save, click, download, watch, reply, buy |

**Promotion workflow.** Mechanic, then pairing with original source material, then draft,
then ethical review, then publication.

**Refresh.** "A swipe file becomes smarter when you track which mechanics work." Use
campaign tracking labels to identify which mechanics drive engagement.

**Over-engineering warning.** "A folder with 400 posts tagged across 15 dimensions is also
useless, too much friction to maintain."

## Claims this source supports

1. A content bank is a structured record, not a pile of quotes. Each entry carries typed
   metadata so it can be retrieved by need later.
2. The metadata fields that recur in practice are hook type, structure pattern, proof
   method, and audience problem. This skill's seed record is a direct adaptation.
3. There is an explicit ethical review step between draft and publication in an
   established content system. This skill's confidentiality screen and attribution gate
   occupy that slot.
4. Banks fail by over-engineering. Keeping the seed record to a small fixed field set is a
   deliberate design choice with a stated failure mode behind it.
5. Ten to fifteen seeds per week is a defensible bank size against the "400 tagged posts
   is useless" warning, though the source names no specific number. **Cadence is a gap in
   this archive: no source found states an evidenced weekly volume.**
