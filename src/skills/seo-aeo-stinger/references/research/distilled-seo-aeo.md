Dense, cited synthesis of the raw archive in `raw/`. Every claim traces to a source file. Research window: last 6 months (2026-02-14 onward) plus official docs of any date. Fetched 2026-08-14.

## 1. Metadata and head management (Svelte 5 / SvelteKit)

| Claim | Source |
| --- | --- |
| `<svelte:head>` inserts elements into `document.head`; may only appear at a component's top level, never inside a block or element. | [raw/seo-aeo--sveltekit-metadata--svelte-head-docs.md] |
| During SSR, `<svelte:head>` content is written into the HTML response, so a crawler running no JavaScript still sees title/description/canonical; it also updates reactively on client navigation. | [raw/seo-aeo--sveltekit-metadata--svelte-head-docs.md], [raw/seo-aeo--sveltekit-metadata--svelte-dev-seo-docs.md] |
| Canonical pattern: return SEO data (title, description, canonical) from a `load` function, feed it into `page.data`, render via `<svelte:head>` in the root layout or per-route component. | [raw/seo-aeo--sveltekit-metadata--svelte-dev-seo-docs.md], [raw/seo-aeo--sveltekit-metadata--rendering-config-seo-architecture.md] |
| Use `+page.server.ts` (server-only load) when SEO data needs secrets, DB access, or request headers -- its return value is embedded in the initial HTML. `+page.ts` (universal load) runs server-side on first request, client-side on navigation; both are safe for SEO because the first response is always server-rendered. | [raw/seo-aeo--sveltekit-metadata--rendering-config-seo-architecture.md] |
| Never compute canonical URLs from `window.location` inside a component -- resolve them server-side in `load` and pass as data, otherwise the canonical is missing from the crawler-visible HTML. | [raw/seo-aeo--sveltekit-metadata--rendering-config-seo-architecture.md] |
| Never fetch SEO-critical data in `onMount()` -- it is client-only and ships with empty metadata on first paint; a crawler that doesn't execute JS sees nothing. | [raw/seo-aeo--sveltekit-metadata--rendering-config-seo-architecture.md] (corroborated in research window by community sources, not independently archived) |
| `ssr = false` on a route/layout renders an empty shell -- the single most common cause of thin/unindexed SvelteKit pages. Never set it on indexable routes. | [raw/seo-aeo--sveltekit-metadata--rendering-config-seo-architecture.md] |
| For CMS-driven dynamic routes, export an `entries()` function from `+page.ts`/`+page.server.ts` so the prerenderer can enumerate every slug at build time. | [raw/seo-aeo--sveltekit-metadata--rendering-config-seo-architecture.md] |

| Claim | Source |

## 6. AEO / GEO: AI citation

| Claim | Source |
| --- | --- |
| llms.txt is a root-level markdown file (H1 site name, blockquote description, H2 sections of links with one-line descriptions) proposed by Jeremy Howard (Answer.AI) specifically for LLM consumption -- the only major AI-visibility signal designed from scratch for AI rather than adapted from a human- or crawler-oriented format. | [raw/seo-aeo--geo-aeo--llms-txt-definitive-guide.md] |
| llms.txt adoption sits near 7% of public SaaS sites as of Q1 2026 -- it remains differentiating precisely because so few competitors have a populated file. Read by ChatGPT's GPTBot/OAI-SearchBot, Perplexity's PerplexityBot, Anthropic's ClaudeBot; **not** yet read by Google's Gemini as of mid-2026. | [raw/seo-aeo--geo-aeo--geo-tactics-playbook-attrifast.md] |
| Princeton's GEO study (Aggarwal et al., KDD 2024, arXiv:2311.09735) is the foundational peer-reviewed source for AEO/GEO tactics: combined techniques lifted a source's visibility in generated answers by up to ~40%. Per-technique lifts: citing authoritative external sources +115% (for lower-ranked content), adding statistics +41%, adding quotations +28%. | [raw/seo-aeo--geo-aeo--geo-tactics-playbook-attrifast.md] |
| Citation is a two-stage pipeline: selection (which sources the engine picks, from a candidate set) then absorption (how much of the selected source's language survives into the answer; ~32% on average). Selection correlates weakly with classic authority signals -- backlinks r^2=0.038, traffic r^2=0.05 -- and strongly with structural properties. | [raw/seo-aeo--geo-aeo--ai-citations-research-machinerelations.md] |
| Structural predictors of citation, ranked by measured effect: named-entity density +267% citation rate; 15+ Knowledge Graph entities on a page = 4.8x higher AI Overview selection probability; tables +2.5x citation likelihood; FAQ structure +28-40%; schema markup odds ratio 1.31 (strongest single content-feature predictor in a 100,411-citation study); query-passage semantic alignment is 7.3x more predictive than domain authority; median cited sentence is <=10 words (engines extract precise factual statements, not paragraphs). | [raw/seo-aeo--geo-aeo--ai-citations-research-machinerelations.md] |
| Freshness is a real, measured citation factor: ChatGPT's citations average 458 days fresher than organic-search results for the same query; 76.4% of top-cited pages were updated within the last 30 days. | [raw/seo-aeo--geo-aeo--ai-citations-research-machinerelations.md] |
| Crawler accessibility is a binary gate applied before any content-quality evaluation -- paywalled, login-walled, or aggressively bot-blocked pages are excluded from citation eligibility entirely, independent of content quality. This is the same failure mode as blocking AI crawlers in robots.txt (Section 2). | [raw/seo-aeo--geo-aeo--ai-citations-research-machinerelations.md], [raw/seo-aeo--robots--ai-crawlers-2026-yatna.md] |
| Top-3 Google-ranked pages are ~34x more likely to be AI-cited than pages ranked 11-30 in the same study -- classic SEO ranking is the gate, structural GEO optimization determines who gets cited among pages that clear it. Traditional SEO and GEO are not competing priorities; SEO fundamentals remain the prerequisite. | [raw/seo-aeo--geo-aeo--ai-citations-research-machinerelations.md] |
| Structural optimization alone (macro/meso/micro document structure, independent of new content) produced a measured 17.3% citation-rate improvement in a controlled framework (GEO-SFE, Yang et al. 2026). | [raw/seo-aeo--geo-aeo--ai-citations-research-machinerelations.md] |
| Per-engine source behavior differs materially: ChatGPT favors Wikipedia/editorial sites (~7 sources, high extraction depth per source); Perplexity favors YouTube/news (~16 sources, strongest freshness bias, shallower extraction per source); Google AI Overviews leans on YouTube and inherits classic Google Search ranking signals; Claude is the most conservative citer, favoring institutional/brand domains and never surfacing YouTube/Wikipedia/Reddit in the tracked sample. ChatGPT's cited URLs overlap only 10% with Google's top-10 for the same queries -- optimizing Google rank alone does not guarantee AI citation share. | [raw/seo-aeo--geo-aeo--ai-citations-research-machinerelations.md] |
| Market concentration: the top 15 domains capture 68% of all consolidated AI citation share across major engines -- a far more extreme concentration than traditional search, and those domains share machine-legible structure, syndication, and clean attribution as common traits. | [raw/seo-aeo--geo-aeo--ai-citations-research-machinerelations.md] |

**Conflict flagged:** sources disagree on whether llms.txt itself measurably moves citation outcomes. `llmstxt-definitive-guide` (a vendor selling llms.txt tooling) treats it as foundational; `geo-tactics-playbook-attrifast` rates its citation lift only "Medium" and explicitly notes Gemini does not read it. No source in this archive provides a controlled before/after measurement isolating llms.txt from the rest of the "three-piece set" (llms.txt + FAQ schema + citable-stats tables) that vendor content bundles together. Preferred reading: ship it (near-zero cost, some engines do read it) but do not present it as a primary lever -- crawler access, server-rendered content, schema, and answer-first structure are the levers with controlled-study evidence (Aggarwal et al. 2024; "SEO Floor" study).

| Claim | Source |

## 9. Technical: trailing slash, redirects, 404s

| Claim | Source |
| --- | --- |
| SvelteKit strips trailing slashes by default (`trailingSlash = 'never'`); `/foo/` redirects to `/foo`. Search engines treat `/foo` and `/foo/` as distinct URLs, so an inconsistent policy creates duplicate-URL problems. Set explicitly per route/layout; `'always'` and `'ignore'` are the alternatives, `'ignore'` is not recommended. | [raw/seo-aeo--technical--sveltekit-routing-errors-trailingslash-docs.md] |
| A confirmed SvelteKit bug (fixed via later PRs) can strip a configured `'always'` trailing slash during client-side hydration/navigation if the nearest `+error.svelte` boundary sits below the `trailingSlash` config layer, occasionally producing an infinite redirect loop. Mitigation: define `trailingSlash` at or above the layer containing the relevant `+error.svelte`. | [raw/seo-aeo--technical--sveltekit-routing-errors-trailingslash-docs.md] |
| For scoped 404 handling under a route subtree, add a `[...path]` catch-all route and explicitly throw `error(404, ...)` from it -- a bare nested `+error.svelte` without a matching catch-all route never renders, because SvelteKit routing fails to match any route at all for an unmatched deep path (only the root `+error.svelte` renders). | [raw/seo-aeo--technical--sveltekit-routing-errors-trailingslash-docs.md] |
| `redirect(308, location)` is the correct status for permanent canonical/URL migrations -- it keeps the request method and transfers SEO value, functionally equivalent to a classic 301 for search-engine purposes. `307` is temporary (keeps method); `303` is for post-form-submission redirects (forces GET). | [raw/seo-aeo--technical--sveltekit-routing-errors-trailingslash-docs.md] |
| A `redirect()` call inside a universal `load` function running client-side (not the initial server-rendered request) does not send a real HTTP status code -- the browser performs an internal `goto(..., { replaceState: true })`-equivalent navigation. Audit redirect status codes against the server-rendered first-load response (e.g. via `curl`), not client-side behavior, since the same code path can be a true HTTP 308 on first load and an invisible client navigation afterward. | [raw/seo-aeo--technical--sveltekit-routing-errors-trailingslash-docs.md] |

**Gap flagged:** the research archive does not contain a dedicated primary source on `hreflang` implementation specifically inside SvelteKit (no i18n-routing source was archived this pass, since the target stack brief did not specify multi-locale requirements). Guides in this skill therefore mark hreflang as "implement via `<link rel="alternate" hreflang>` tags emitted from the same `svelte:head` metadata pipeline used for canonical, following the general hreflang spec" and flag it as a gap requiring project-specific research if a multi-locale site is in scope -- do not guess at a SvelteKit-specific hreflang library or convention beyond this.
