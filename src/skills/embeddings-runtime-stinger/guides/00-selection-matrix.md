# Selection matrix: which embedding model and which runtime

Walk this before writing any embedding call. Grounded in `references/research/raw/openai--vector-embeddings-guide.md`, `references/research/raw/cohere--embed-api-v2-reference.md`, `references/research/raw/voyageai--text-embeddings-model-choices.md`, `references/research/raw/voyageai--pricing.md`, and `references/research/raw/qdrant--how-to-choose-an-embedding-model.md`.

## First question: hosted provider or self-hosted?

| Factor | Favors hosted (OpenAI, Cohere, Voyage) | Favors self-hosted (transformers.js / local model) |
|---|---|---|
| Operational capacity | No GPU/CPU capacity planning, no model updates to manage, zero ops burden | Team already runs infrastructure and wants to own the runtime |
| Cost shape | Pay-per-token, no fixed cost, scales down to zero at rest | No per-token billing; cost is fixed footprint + CPU/GPU regardless of volume |
| Quality ceiling | Frontier proprietary models generally lead open-weight local models on retrieval benchmarks | Open-weight local quality is close enough for the workload, or domain-tuned local models win |
| Data locality / privacy | Data leaves the machine (needs a data-egress review, see `security-worker-bee`) | Nothing leaves the machine; the right default when the text is private or regulated |
| Latency | Network round-trip per call (or batch), typically 50-400ms | No network hop, but pays a one-time warmup cost and ongoing CPU/GPU at inference |
| Volume | Low-to-moderate volume where per-token cost stays small | High, predictable, sustained volume where per-token cost becomes a real line item |
| Time to first working call | Minutes: sign up, get an API key, call the endpoint | Longer: install the runtime, pull/convert the model, wire up caching and batching |

There is no universal winner. The Qdrant embedding-model-selection guide frames this explicitly as a genuine tradeoff, not a default either way (source: qdrant--how-to-choose-an-embedding-model.md): teams without ops capacity lean hosted even at a per-token premium; teams with budget constraints or an existing ops function, or a hard privacy requirement, lean self-hosted.

**Practical default for a new feature on this repo's stack:** start hosted (OpenAI or Voyage, see below) for time-to-first-query and zero ops burden. Move a specific, high-volume, predictable workload to self-hosted only when a measured signal, not a hunch, shows the per-token cost becoming a real line item, or when the text is privacy-bound and cannot leave the machine.

## Hosted provider comparison

| Provider | Model(s) | Native dimension | Matryoshka truncation | Asymmetric input handling | Notable |
|---|---|---|---|---|---|
| OpenAI | `text-embedding-3-small` | 1536 (default) | Yes, via `dimensions` param | None (symmetric) | $0.02/M tokens; MTEB 62.3% |
| OpenAI | `text-embedding-3-large` | 3072 (default) | Yes, via `dimensions` param | None (symmetric) | $0.13/M tokens; MTEB 64.6% |
| Cohere | `embed-v4.0` | 1536 (default) | Yes, via `output_dimension` (256/512/1024/1536) | Required: `input_type` = `search_document` / `search_query` / `classification` / `clustering` | Also returns quantized `embedding_types` (int8/uint8/binary/ubinary/base64) in the same call |
| Voyage AI | `voyage-4-large` / `voyage-4` / `voyage-4-lite` / `voyage-code-4` | 1024 (default) | Yes, via `output_dimension` (256/512/1024/2048) | Optional but recommended: `input_type` = `query` / `document` (prepends a fixed prompt) | $0.02-$0.12/M tokens depending on tier; 200M free tokens/account; 33%-discounted async Batch API |

See `guides/hosted-01-openai.md`, `guides/hosted-02-cohere.md`, and `guides/hosted-03-voyage.md` for the full call shape, request limits, and pricing detail on each.

### How to choose among the three hosted providers

1. **Dimension fit against the target column first** (per `00-principles.md` principle 1). All three support request-time dimension reduction via Matryoshka truncation, so this is rarely the deciding factor unless the target column is unusually narrow.
2. **Asymmetric embedding discipline.** Cohere requires `input_type`; Voyage strongly recommends it. If the codebase's write path and query path are maintained by different people or generated by different code paths, a provider that *requires* the parameter (Cohere) forces the discipline; a provider where it's optional (Voyage, and OpenAI has no equivalent at all) relies on the team remembering to apply it consistently. See `00-principles.md` severity rubric: an asymmetric-embedding mismatch between write and query paths is a must-fix.
3. **Cost at the project's actual volume.** OpenAI's small model and Voyage's lite tier are priced comparably; OpenAI's large model and Voyage's top tier are priced comparably; run the numbers against the actual token volume rather than picking on sticker price alone (see `references/research/distilled-embeddings-runtime.md` for the archived pricing detail and its freshness caveat).
4. **Batch/backfill discount if doing a large one-time job.** Both OpenAI and Voyage offer an async batch lane at a discount versus the synchronous endpoint; use it for backfills and model-swap re-embeds (see `guides/01-batching.md`).
5. **Retrieval quality on this project's actual data**, per `00-principles.md` principle 2. Do not decide on MTEB rank alone.

## Self-hosted local option

The local-daemon material in `guides/local-daemon-*.md` (transformers.js + nomic-embed-text-v1.5, 768-dim, q8, Unix-socket daemon) is one fully documented self-hosted implementation, proven in production for the Hivemind product. `guides/local-daemon-06-local-vs-hosted.md` is the Hivemind-specific worked example of this same local-vs-hosted decision. For a from-scratch self-hosted setup on a different embedding model, `references/research/raw/huggingface--transformersjs-node-server-side-inference.md` documents the general transformers.js server-side pattern (singleton warm pipeline, `env.cacheDir`, `env.localModelPath`, `env.allowRemoteModels = false` for fully offline operation) independent of which model is loaded into it.

## Quick decision table

| If the project is... | Default to |
|---|---|
| A new feature on this repo's SvelteKit + Neon + pgvector stack, moderate volume, no hard privacy constraint | A hosted provider (`guides/hosted-01-openai.md` to start; compare Voyage if cost at volume matters) |
| High-volume, predictable, and the per-token bill is becoming a real line item (measured, not assumed) | Self-hosted local model (`guides/local-daemon-*.md` as the worked implementation) |
| Text that cannot leave the machine (regulated data, contractual restriction) | Self-hosted local model, regardless of cost math |
| Already running the Hivemind local-daemon setup and evaluating a swap | Stay local unless a hosted provider shows a measured recall win *and* the dimension/cost tradeoff clears the bar in `guides/local-daemon-03-model-selection.md` |
| Doing a one-time bulk backfill or model-swap re-embed, any provider | Use the provider's async batch/discount lane; see `guides/01-batching.md` |
