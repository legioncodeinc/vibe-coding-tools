## Key facts

- "Simple: Generate Private Integration tokens from your account settings and manage them with ease. Secure: You get to restrict the scopes/permissions that a developer can access on your account."
- Comparison table (Private Integrations vs OAuth Access Tokens):
  | Private Integrations | Access Tokens |
  |---|---|
  | Generated from the UI: Private Integration token can be generated easily from the UI | Programmatic Generation: API Tokens are generated by exchanging OAuth access code for the tokens using Get Access Token API |
  | Static/Fixed: Private Integration Tokens are static/fixed and do not automatically refresh unless you rotate them from the UI | Refreshed Daily: Access Tokens expire daily and need to be refreshed |
- Creation flow: "Step 1: Click on 'Create new Integration'. Step 2: Give your Private Integration a name and description... Step 3: Select the scopes/permissions that you want the private integration to have access to on your agency account. Ensure that you are selecting only the required scopes for better data security. Step 4: Copy the token generated and share it with your third-party app developer... Note: Don't forget to copy the token generated as you won't be able to do it again later."
- Limit: "Users can create up to 5 Private Integration Tokens (PIT) at both the Agency level and the Location level."
- Editable after creation: "Yes, you can edit the Private Integration name, description and scopes/permissions any time after you've created it."
- Default permission holder: "By default, agency admins have the ability to create and manage Private Integrations" (customizable via Settings > Team > Roles & Permissions per the Growthable secondary source).

## Usage

- Header format: `Authorization: Bearer <YOUR_PRIVATE_INTEGRATION_TOKEN>` -- must include the literal word `Bearer` followed by a space; unlike legacy API keys, the token is not pasted bare.

## Notes for the distillation

PIT is UI-generated, static (does not auto-refresh, must be manually rotated), scoped like an OAuth token, and capped at 5 per level (agency or location) -- these are hard operational limits worth surfacing in the auth decision matrix. Contrast with OAuth access tokens, which are generated programmatically and expire daily (~86,399s per `ghl--auth--agency-vs-location-access-tokens.md`).
