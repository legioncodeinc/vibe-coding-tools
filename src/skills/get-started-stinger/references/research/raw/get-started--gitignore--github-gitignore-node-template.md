`github/gitignore` (173K+ stars) is GitHub's own collection of `.gitignore` templates — the same set that populates the template chooser when creating a new repository on GitHub.com. The root of the repo holds templates "in common use" for popular languages/tools; `Global/` holds editor/OS/tool templates meant to be merged into project templates or added to a machine-global ignore file; `community/` holds specialized/versioned templates for narrower tools.

## What makes a good gitignore template (repo's own contribution bar)

A template must curate "a meaningful set of rules to help get started" for a language/framework/tool — not just enumerate every file a specific software version installs (those belong in `community/` instead). Versioned templates (where behavior changes significantly release to release) live under `community/` with the version embedded in the filename; the root-level template stays "evergreen" (no version in the name, always tracks current).

## Synthesis for a TS/Node `.gitignore` template (cross-referenced against a generator source, DevZone Tools, `.gitignore` for Node.js + TypeScript, 2026-05-28 snapshot)

Combining the Node ecosystem side (`node_modules/`, package-manager debug logs, `.env*`) with the TypeScript compiler side (`dist/`, `build/`, `*.tsbuildinfo`, source maps) is the standard pairing — TypeScript projects compiled with `tsc` emit fully reproducible JS to `dist/`/`build/`/`out/`, which should never be committed, and `*.tsbuildinfo` caches are machine-specific incremental-build state. `.gitignore` should always be committed itself so every collaborator shares the same rules; adding a file to `.gitignore` does not retroactively untrack a file already committed — that needs `git rm --cached <path>`.
